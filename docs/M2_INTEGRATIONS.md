## Interpretation limitations

Strict payment/evidence validation can reject a syntactically valid model response. In the initial corpus batches, some direct models produced pixel/0–1000 boxes or inconsistent observation states; these are failures, never silently rescaled or repaired. Native document fields do not prove account ownership, and invoice totals do not become amount due. Supplier names do not become beneficiaries. All completed drafts still require confirmation; completion rate is not accuracy.

`rules@2` handles contiguous bank-label sections across blank lines, explicit markdown cells and Croatian model/reference instructions with synthetic counterexamples. Full-corpus saved-observation replay covers all 31 recordings for each of Mistral, Google, AWS text and paced Azure Read (124 input recordings). Six Mistral, one Google, one AWS and zero Azure payment structures changed versus rules 1; no quality score is attached. The normalized observation retains native layout, but a general geometric association engine remains M3 work.

Version limits: Google requests an explicit processor version; direct LLM profiles record requested and returned model names. Azure prebuilt IDs and AWS operations are service-managed selections, with returned API/model metadata preserved where supplied. Mindee profile labels identify the dated operator configuration and hashed private resource binding, not immutable vendor model weights. Their schema/account readbacks and raw responses remain private evidence; provider-side revisions are not independently controllable. Mistral's annotation API identifies OCR 4.1 but does not expose a separately pinned internal annotation model. These unknowns must remain visible in cost/quality comparisons.


Prompt/schema issue identified during initial evaluation: `payment-image@2` tells models boxes are optional but does not specify normalized `[x,y,width,height]`, and its provider-facing `Claim` schema has four numeric entries without the result schema's 0–1 bounds. Local `Evidence` validation correctly rejects pixel/0–1000 boxes. Protocol3 now makes that convention explicit with synthetic tests and separately labelled full-corpus evaluation. Do not rescale or discard malformed boxes silently, weaken the result contract, or rewrite the baseline failures. This is distinct from account/transport compatibility.

Account-limit follow-ups supersede the initial unknown-tier/readiness observations: Azure explicitly identified its F0 tier in a429 response; [Microsoft's quota guidance](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/service-limits?view=doc-intel-4.0.0) covers separate analyze/get limits and recommends slower polling. New profiles use five-second initial/poll delays and sequential Azure batches. AWS processing returned `SubscriptionRequiredException`, and its console redirected to registration/free-plan restrictions. The dedicated IAM user lacks billing visibility; the user subsequently confirmed upgrading the account to a paid plan. Fresh full-corpus AWS matrices are recorded under the seventh plan, and both AWS operations then completed all 31 inputs successfully. [AWS plan documentation](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans.html) distinguishes limited Free-plan access from paid pay-as-you-go access; it does not prove which activation step this particular account needs. The account upgrade was performed by the user, not by this agent.


The explicit `protocol_version=3` vision revision now adds normalized coordinate instructions and0–1 item bounds to the provider schema. Prompt-JSON mode also accepts a single complete JSON Markdown fence wrapper, while rejecting extra prose and retaining strict validation inside it. Full original raw responses remain unchanged. Synthetic tests cover valid fences, extra prose, invalid boxes and the unchanged version2 behavior. Fresh full-corpus Anthropic/Together v3 batches are separate from all earlier attempts and from the saved-response parser replay; they do not revise old results.

The paced Azure Read and Invoice profiles both completed all 31 inputs successfully. The earlier throttle failures remain separate uncertain-charge records; no Azure tier change was made.

## Compact extraction revision, 7 October

Protocols 4/5 use a smaller provider-facing schema. Models return printed readings and their basis; the backend generates evidence IDs and review states. Protocol5 uses typed destinations to prevent redundant route fields contradicting each other. It preserves leading zeros, ambiguity, inferred values and unresolved identifiers. Model excerpts remain unverified claims with no invented coordinates. The public v1 contract and protocols1–3 are unchanged. Under the historical strict policy, invalid or contradictory output failed the whole response. The 8 October field policy below supersedes that behavior for newly versioned selected compact profiles.

[Together reasoning documentation](https://docs.together.ai/docs/inference/chat/reasoning) identifies Qwen3.5-9B as reasoning-on by default. The revised profile explicitly disables thinking and includes the schema in the prompt as recommended by [Together structured-output guidance](https://docs.together.ai/docs/inference/chat/structured-outputs). The original v3 batch had 27 timeouts; the typed revision completed 31 attempts with 30 accepted drafts, one contradictory unreadable/value claim and no timeouts. This establishes a working configuration, not a controlled attribution of the speedup to one change.

Google Invoice mapping2 converts explicit currency symbols to ISO codes while preserving raw evidence. After the user refreshed ADC, a new 31-image batch accepted all31 outputs. The earlier 12 mapping failures remain unchanged. Gemini prompt-JSON still sometimes wraps enum fields as reading objects; native schema enforcement is evaluated separately with the compact format.

Private compatibility plans, exact profiles, batch states and diagnosis are under `.local/m2-compat-2026-10-07/`. Abandoned version4 attempts remain explicit incomplete matrices; they were superseded by new full-corpus version5 batches, never rewritten as successes.

The final Gemini protocol 6 changes fixed-tag `const` constraints to equivalent one-value `enum` constraints, following the supported [Google JSON Schema subset](https://ai.google.dev/gemini-api/docs/structured-output). This is request compilation, not response repair; old protocol 5 requests are preserved. Its fresh full 31-image result is recorded in IMPLEMENTATION_STATUS.md. The compatibility revision suite had 353 tests, 94.60% statement / 87.73% branch coverage; v1 contract exports are byte-identical.
